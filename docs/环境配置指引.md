# RPG 项目环境配置指引

本项目在本机运行 Node.js 后端与网页。文字模型通过用户提供的 API 调用；本地图片生成是可选功能。仅玩文字冒险不需要 NVIDIA 显卡、Python、CUDA、ComfyUI 或模型权重。

## 1. 环境要求

| 项目 | 文字游戏 | 可选本地图片生成 |
|---|---|---|
| 系统 | 本指南按 Windows 10/11 x64 操作 | 自动安装目前支持 Windows x64 |
| Node.js | 22 或更高版本，含 npm | 使用同一游戏后端 |
| 浏览器 | 当前 Chrome、Edge 等浏览器 | 使用同一网页 |
| 网络 | 首次安装 Web 依赖、调用线上模型时需要 | 首次下载程序、依赖与权重需要 |
| GPU / 内存 / CPU | 文字功能无专用 GPU 门槛 | 由网页按所选模型检测，见第 6 节 |

完整工程若带有 `ai/runtime/node/node.exe`，启动脚本优先使用这个运行时。仅从 Git 克隆的工程不包含机器安装目录，应先安装 [Node.js LTS](https://nodejs.org/en/download)，确认版本至少为 22。系统 Node 安装后重新打开终端，运行 `node --version` 和 `npm.cmd --version` 检查。

## 2. 安装依赖与启动

### Windows 双击运行

1. 把工程放在可写目录，例如 `F:\role_play2`，避免需要管理员权限的系统目录。
2. 首次使用或代码更新后，运行根目录的 `安装项目依赖.bat`。它安装后端与前端锁定依赖，再构建网页；不安装图片模型。
3. 运行 `启动游戏.bat`，保持窗口打开。浏览器打开 `http://127.0.0.1:8000/`。
4. 首次启动会生成 `web/config.json`，API 地址、模型 ID 和密钥均留空，并自动打开网页设置。
5. 按第 3 节填写 API，保存后即可新建或加载冒险存档。

若完整工程已带 `web/node_modules`、`web/client/node_modules` 和 `web/client/dist`，可直接启动。修改前端源码后必须重新构建；更新后端代码后要重新启动游戏。单独修改模型配置无需重启。

### 终端操作

使用系统安装的 Node/npm，在工程根目录执行：

```powershell
npm.cmd --prefix web ci
npm.cmd --prefix web/client ci
npm.cmd --prefix web/client run build
node web/server/index.js 8000
```

若仅使用工程内 Node/npm，可执行 `安装项目依赖.bat` 和 `启动游戏.bat`；安装脚本会设置所需的 Node 路径。

端口被占用时，可在终端执行 `& '.\启动游戏.bat' 8001`，然后打开 `http://127.0.0.1:8001/`。Ctrl+C 停止服务器。项目默认监听 `127.0.0.1`，供本机浏览器访问。

## 3. 在网页配置文字大模型

点击顶部模型名称或右上角「设置」，在「文字大模型」中选择接入方式：

| 接入方式 | 配置内容 | 运行行为 |
|---|---|---|
| 通用模型 API | API 基础地址、模型 ID、认证方式、API Key | 调用所填服务的 Chat Completions 接口 |
| Kimi 登录 | 已通过 Kimi Code 登录的当前用户凭证 | 明确复用 Kimi Code 凭证，按既有接口调用 |
| 演示模式 | 无需 API | 本地示例回复，供体验界面与规则流程 |

新环境默认选择「通用模型 API」，但配置留空时只运行示例回复。程序不会扫描登录后自动选择 Kimi。升级时原配置明确启用的 Kimi 登录会保留，用户可在网页改成通用 API。

### 通用 API 的填写方式

1. **API 基础地址**：填写服务商给出的 OpenAI 兼容基础地址，例如 `https://你的服务域名/v1`。后端会加上 `/chat/completions`；若粘贴完整聊天端点，也会自动去掉这一段后缀。地址支持 HTTP/HTTPS，不接受 URL 内嵌账号密码、查询参数或片段。
2. **模型 ID**：填写服务控制台列出的精确模型名。模型 ID 不是展示名，必须是当前账号有权限使用的 ID。
3. **认证方式**：线上服务一般选「Bearer API Key」，填写对应密钥。没有认证的本地兼容服务可选「无需密钥」。
4. **温度 / 超时 / 流式输出**：默认温度 0.8、超时 180 秒、流式输出开启。模型不支持流式时可关闭；模型对温度有特定限制时按服务商要求设置。
5. 点击 **「测试连接」**。它使用表单中的候选配置发送一个很短的聊天请求，最长等待 30 秒，可能产生少量 API 费用；测试不保存配置。测试成功表示当前地址、认证、模型 ID 和基本聊天协议可用，不代表游戏输出质量已经验证。
6. 点击 **「保存配置」**。顶部显示实际模型 ID，下一次游戏行动使用新配置；当前已开始的回合仍用开始时的配置。

保存后再打开设置，密钥输入框保持空白并显示已保存标记。**同一地址留空表示保留密钥**；勾选「清除已保存密钥」会清除。更换 API 地址、认证方式或接入模式而没有填写新密钥时，会清除旧密钥，避免发送给新服务。

### 服务商地址的参考

本项目支持 **OpenAI Chat Completions 兼容协议**。服务商的原生 Anthropic Messages、原生 Gemini generateContent 等协议，需要其提供的兼容端点或转换网关。

| 服务 | 基础地址填写原则 | 说明 |
|---|---|---|
| DeepSeek | 官方当前给出的 `https://api.deepseek.com` | 模型 ID 按控制台可用模型填写，参考 [DeepSeek 官方接口说明](https://api-docs.deepseek.com/) |
| 阿里云百炼 Qwen | 从控制台复制对应工作空间、地域的 OpenAI 兼容基础地址 | API Key、地域和地址应匹配，参考 [百炼兼容接口说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope) |
| 本地服务 / 自建网关 | 例如 `http://127.0.0.1:1234/v1`，端口以实际服务为准 | 先启动模型服务，填其对外的模型 ID；是否需要密钥由服务决定 |
| 其他兼容服务 | 按服务商控制台填写 | 请求使用 `model`、`messages`、`temperature`、`stream`；应支持聊天回复或 SSE 文本片段 |

文字用的 Qwen API 与本地图片用的 Qwen-Image 是独立配置。选择其中一个不会自动安装另一个。

### Kimi 登录的兼容选项

只在明确选择「Kimi 登录」时读取当前用户的 `~/.kimi-code/credentials/kimi-code.json`。需先通过 Kimi Code 自身的登录流程获得凭证；本项目没有替用户开通账号。该选项维持已有的 Kimi Code 接口、模型配置与温度约束。

启动日志中的 `kimi-oauth` 表示当前配置选择了这种认证方式，不能用它判断项目只支持 Kimi。通用 API 可接入其他兼容服务，包括使用 API Key 的 Moonshot 服务；其地址和模型 ID 应从对应服务控制台获取。

## 4. 配置文件与迁移

实际文件是 `web/config.json`。示例文件 `web/config.example.json` 不带个人密钥，可作为手工配置参考。API 模式的最小例子：

```json
{
  "llm_mode": "api",
  "api_auth": "bearer",
  "base_url": "https://你的服务域名/v1",
  "api_key": "填写自己的密钥",
  "model": "填写精确模型ID",
  "temperature": 0.8,
  "stream": true,
  "timeout": 180,
  "kimi_oauth": { "enabled": false },
  "image_generation": { "enabled": false }
}
```

| 字段 | 含义 |
|---|---|
| `llm_mode` | `api` / `kimi-oauth` / `demo`，决定实际接入方式 |
| `api_auth` | API 模式的 `bearer` 或 `none` |
| `base_url` / `model` | 用户选择的兼容接口与模型 ID |
| `api_key` | 本机保存的 API 密钥；无认证服务可为空 |
| `temperature` / `stream` / `timeout` | 生成温度、流式开关和秒数超时 |
| `kimi_oauth` | 专用 Kimi 登录的凭证路径等选项，启用状态随 `llm_mode` 保存 |
| `image_generation` | 可选本地生图配置，启用状态由网页检测安装流程写入 |

网页保存时先写临时文件，再替换配置文件。下一次启动会读取已保存配置；网页读取只返回密钥是否存在与掩码，不回传完整密钥。配置、存档、下载权重和生成图片均不进入 Git。密钥在本机 JSON 中以明文保存，分享工程前去掉个人 `web/config.json`，改用无密钥示例文件。

迁移文字配置时复制自己的 `web/config.json` 即可。Kimi 登录凭证位于用户目录，需在新机器重新登录或按原工具的流程迁移。旧配置没有 `llm_mode` 时保留明确的旧 Kimi 登录选择；其他旧 API 配置按通用 API 处理。图片配置需要在新机器重新检测，不能靠手工改 `enabled` 跳过环境校验。

## 5. 项目目录

```text
role_play2/
├── 安装项目依赖.bat          安装 Node Web 依赖与构建网页
├── 启动游戏.bat              优先使用工程内 Node，启动本机后端
├── docs/环境配置指引.md      本指引，网页 /guide 也可打开
├── core/                    RPG 核心规则
├── modules/                 冒险本内容
├── web/
│   ├── config.json          本机模型设置，首次启动生成
│   ├── config.example.json  无密钥示例
│   ├── server/              配置、API、GM、存档和生图服务
│   ├── client/src/          Vue 网页源代码
│   ├── client/dist/         构建后的网页
│   ├── saves/               玩家存档
│   └── assets/              已生成图片
└── ai/
    ├── runtime/             本机 Node / 按需安装的 Python
    ├── vendor/ComfyUI/      按需安装的 ComfyUI
    ├── models/              按需下载的图片模型权重
    └── data/                安装任务、缓存与日志
```

完整复制工程离线使用时，需携带已安装的 Web 依赖和前端构建；已配置本地生图时，还需携带 `ai/runtime/python`、`ai/vendor/ComfyUI` 与 `ai/models`。线上文字模型离线时仍无法调用。

## 6. 可选本地图片生成

默认不配置、不检测、不加载。网页「设置 → 图片生成（可选）」打开「配置本地图片生成」，选择模型，点击「检测并配置」。

检测的是运行后端的机器，包括 GPU、显存、CUDA 算力和驱动、内存、CPU 逻辑线程以及磁盘空间。达标后自动下载并配置工程内 Python、ComfyUI、依赖和权重；已有完整安装会校验复用。只有全部成功才启用，真正生成图片时才启动模型。

| 当前配方 | NVIDIA 显存 | 内存 | CPU 逻辑线程 | 模型文件大小 |
|---|---:|---:|---:|---:|
| Z-Image-Turbo + Qwen3 | ≥ 16 GiB | ≥ 32 GiB | ≥ 4 | 约 19.27 GiB |
| Qwen-Image 2512 FP8 | ≥ 24 GiB | ≥ 48 GiB | ≥ 8 | 约 28.00 GiB |

当前自动安装策略还要求 Windows x64、CUDA 算力 ≥ 8.0、NVIDIA 驱动 ≥ 570.65，并需要额外的程序、依赖和临时磁盘空间。以网页检测报告为准；这些是项目当前配方的保守门槛。完整 Qwen-Image 2512 配方尚未完成本机实际生图验证。

不达标时网页给出失败项并建议使用图片 API；图片 API 目前只提供提示，尚未实现接入。关闭图片开关会停止项目创建的生图进程、取消配置任务，保留已下载文件供下次复用。完整说明见 `ai/README.md`。

## 7. 常见问题

| 现象 | 处理方式 |
|---|---|
| 找不到 Node / npm 或版本过低 | 安装 Node.js 22 以上的 LTS，重新打开终端；也可使用工程内完整 Node/npm |
| 启动提示缺少 Web 依赖或构建产物 | 运行 `安装项目依赖.bat`，成功后重启 |
| 安装出现 npm 网络错误 | 检查网络与本机代理，再运行依赖安装脚本；不要删除自己的配置或存档 |
| 网页显示未配置或示例回复 | 在设置填完整 API 地址、模型 ID、认证方式和所需密钥，再保存 |
| 测试成功但刷新又是旧配置 | 测试不保存，必须点击「保存配置」 |
| 401 / 403 | 检查密钥、账号权限和服务地域；更换地址后需填写新密钥 |
| 404 | 检查基础地址及其 `/v1` 等路径；确认提供 Chat Completions 兼容端点 |
| 400 / 模型不存在 / 温度不支持 | 使用控制台的精确模型 ID，按模型要求调整温度；确认请求协议支持 |
| 超时、连接拒绝或流式失败 | 检查服务是否启动、网络/代理和端口；按需提高游戏超时，尝试关闭流式输出 |
| 游戏回复不能正确结算 | 基本连接成功不保证输出协议质量，使用遵守系统提示并能输出 JSON 的聊天模型 |
| 配置无法保存 | 确认工程目录可写、JSON 合法，避免只读或管理员权限目录 |
| 端口 8000 被占用 | 给启动脚本传其他端口，如 8001 |
| 本地图片配置失败 | 查看网页失败项和 `ai/data` 中安装记录/日志，重试时复用下载断点 |

## 8. 开发验证

在工程根目录运行：

```powershell
npm.cmd --prefix web test
node web/server/engine/verify-parity.mjs
npm.cmd --prefix web/client run build
```

`npm test` 使用离线模型或本机假服务、临时配置与内存存档，不使用个人线上 API Key。parity 校验使用独立夹具，避免写入玩家存档。本地 GPU 实际出图验证会加载权重，应按 `ai/README.md` 中的显式验证命令执行。

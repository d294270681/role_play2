# RPG 项目环境配置指引

本项目在本机运行 Node.js 后端与网页。文字模型通过用户提供的 API 调用；本地图片生成是可选功能。仅玩文字冒险不需要 NVIDIA 显卡、Python、CUDA、ComfyUI 或模型权重。

## 1. 环境要求

| 项目 | 文字游戏 | 可选本地图片生成 |
|---|---|---|
| 系统 | 本指南按 Windows 10/11 x64 操作 | 自动安装目前支持 Windows x64 |
| Node.js | 22 或更高版本，含 npm | 使用同一游戏后端 |
| 浏览器 | 当前 Chrome、Edge 等浏览器 | 使用同一网页 |
| 网络 | 首次安装 Web 依赖、调用线上模型时需要 | 首次下载程序、依赖与权重需要 |
| GPU / 内存 / CPU | 文字功能无专用 GPU 门槛 | 由网页按所选模型检测，见第 6 节 |

完整工程若带有 `ai/runtime/node/node.exe`，启动脚本优先使用这个运行时。仅从 Git 克隆的工程不包含机器安装目录，应先安装 [Node.js LTS](https://nodejs.org/en/download)，确认版本至少为 22。系统 Node 安装后重新打开终端，运行 `node --version` 和 `npm.cmd --version` 检查。

## 2. 安装依赖与启动

### Windows 双击运行

1. 把工程放在可写目录，例如 `F:\role_play2`，避免需要管理员权限的系统目录。
2. 首次使用或代码更新后，运行根目录的 `安装项目依赖.bat`。它安装后端与前端锁定依赖，再构建网页；不安装图片模型。
3. 运行 `启动游戏.bat`，保持窗口打开。浏览器打开 `http://127.0.0.1:8000/`。
4. 首次启动会生成 `web/config.json`，默认 DeepSeek 地址已填写，模型 ID 和密钥留空，并自动打开网页设置。
5. 按第 3 节填写 API，保存后即可新建或加载冒险存档。

若完整工程已带 `web/node_modules`、`web/client/node_modules` 和 `web/client/dist`，可直接启动。修改前端源码后必须重新构建；更新后端代码后要重新启动游戏。单独修改模型配置无需重启。

### 终端操作

使用系统安装的 Node/npm，在工程根目录执行：

```powershell
npm.cmd --prefix web ci
npm.cmd --prefix web/client ci
npm.cmd --prefix web/client run build
node web/server/index.js 8000
```

若仅使用工程内 Node/npm，可执行 `安装项目依赖.bat` 和 `启动游戏.bat`；安装脚本会设置所需的 Node 路径。

端口被占用时，可在终端执行 `& '.\启动游戏.bat' 8001`，然后打开 `http://127.0.0.1:8001/`。Ctrl+C 停止服务器。项目默认监听 `127.0.0.1`，供本机浏览器访问。

## 3. 在网页配置文字大模型

点击顶部模型名称或右上角「设置」，选择「连接模型 API」，然后选择服务：

| 模型服务 | 默认基础地址 | 认证 | 模型协议 |
|---|---|---|---|
| DeepSeek 官方 API | `https://api.deepseek.com` | Bearer API Key | Chat Completions |
| OpenCode Go 订阅 | `https://opencode.ai/zen/go/v1` | Go 订阅的 API Key | 按模型选择 Messages、Responses 或 Chat Completions |
| Anthropic 兼容 API | `https://api.anthropic.com/v1`，可改为兼容网关 | 默认 x-api-key，网关可选 Bearer / 无需密钥 | Anthropic Messages |
| 通用 OpenAI 兼容 API | 服务商或本地服务提供的基础地址 | Bearer / 无需密钥 | Chat Completions |

新环境默认选择 DeepSeek，但密钥和模型未配置时使用本地演示回复，不调用线上模型。也可主动选择「演示模式」。

### 配置步骤

1. 选择服务，确认基础地址。地址可以包含服务商的路径前缀；粘贴 `/chat/completions`、`/messages` 或 `/responses` 完整端点时会移除后缀。不要把 API Key 放进 URL。
2. 填写该服务的 API Key。OpenCode Go 使用订阅账户的密钥，基础路径必须包含 `/go/`；普通 Zen 地址的计费方式不同。
3. 点击「刷新模型」，搜索并选择模型。目录读取使用当前填写的接口和密钥，不保存配置，也不发送生成请求。Go 展示 `/zen/go/v1/models` 返回的全部条目，不使用普通 Zen 的目录。实际账号权限、地区和额度仍以服务响应为准。
4. Anthropic / OpenAI 兼容网关如果没有 `/models` 接口，可手填模型 ID。能力未知的模型仅使用基础协议和输出长度，不发送猜测的思考或采样字段。
5. 配置思考模式、思考等级、输出 tokens、采样参数、超时与流式输出。网页仅启用当前模型支持的选项，后端再次校验。切换服务或模型会重置参数，防止沿用上一个模型的无效等级。
6. 点击「测试连接」。它使用当前模型和参数发送短请求，最多等待 30 秒，使用对应服务的账户额度。成功表示基本接口可用，不代表游戏输出质量已验证；测试不保存。
7. 点击「保存配置」，写入 `web/config.json`。下一次游戏行动读取新配置；进行中的回合使用开始时的配置。

再次打开设置时，密钥框为空并显示尾号。**同一服务、基础地址和认证方式下留空会保留已存密钥**；勾选清除会删除密钥。切换服务、地址、认证或运行方式且未填新密钥时清除旧密钥。

### 思考与参数的实际行为

- **DeepSeek 官方**：模型和推理强度取自官方目录，当前参考模型为 `deepseek-flash` 和 `deepseek-v4-pro`，支持 `low / high / max`。关闭思考时发送 `thinking.type=disabled` 和 `reasoning_effort=none`。思考模式中不发送无效的 temperature；top_p 有效范围为 0.95–1。非思考模式使用 temperature，不发送固定为 1 的 top_p。详见 [官方 Chat Completions 参数](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [模型目录](https://api-docs.deepseek.com/api/list-models/)。
- **OpenCode Go**：模型 ID 和目录实时读取 Go 订阅接口，协议按 [Go 官方端点](https://opencode.ai/docs/go/) 选择。例如 Qwen / MiniMax 使用 Messages，GPT / Grok / Muse 使用 Responses，GLM / DeepSeek 使用 Chat Completions。Go 目录包含的 Kimi 系列也会完整展示，但不再有专用 Kimi 登录或本机凭证读取，选择这些模型时使用 Go 密钥。
- **Anthropic 兼容**：使用原生 Messages 请求、顶层 system、必需的 max_tokens 与 anthropic-version。有预算的旧模型发送 `thinking.budget_tokens`，自适应模型发送 `thinking.type=adaptive` 和 `output_config.effort`。模型未声明的等级不会显示；不可关闭思考的新模型不提供关闭选项。详见 [思考预算](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)、[effort](https://platform.claude.com/docs/en/build-with-claude/effort) 和 [模型能力目录](https://platform.claude.com/docs/en/api/models/list)。

最大输出 tokens 包括模型的思考消耗，需要为正文与末尾 JSON 状态留足空间。发生 token 截断或流提前断开时，本次回合不提交状态，可提高输出上限或降低思考设置后重试。思考块不显示为剧情、不写进存档或网页历史；有签名的内容仅在当前回合内部保留，用于判定后的续写。

模型能力参考目录来自 OpenCode 使用的 [Models.dev](https://models.dev/)；Go 刷新时更新能力，服务原生目录中声明的能力优先。目录不可用时明确提示使用参考或上次目录；参考目录不证明账号当前有调用权限。

## 4. 配置文件与迁移

实际配置为 `web/config.json`，无密钥模板为 `web/config.example.json`。例如 DeepSeek：

```json
{
  "llm_mode": "api",
  "llm_provider": "deepseek",
  "api_auth": "bearer",
  "base_url": "https://api.deepseek.com",
  "api_key": "填写自己的密钥",
  "model": "deepseek-flash",
  "thinking": "enabled",
  "reasoning_effort": "high",
  "max_tokens": 16384,
  "temperature": 1,
  "top_p": null,
  "thinking_budget": 4096,
  "stream": true,
  "timeout": 180,
  "image_generation": { "enabled": false }
}
```

| 字段 | 含义 |
|---|---|
| `llm_mode` | `api` / `demo` |
| `llm_provider` | `deepseek` / `opencode-go` / `anthropic` / `openai-compatible` |
| `api_auth` | `bearer` / `x-api-key` / `none`，DeepSeek 与 Go 固定 Bearer |
| `base_url` / `model` / `api_key` | 服务地址、精确模型 ID 与本机密钥 |
| `thinking` | `default` 或所选模型允许的思考模式 |
| `reasoning_effort` | `default` 或所选模型允许的等级，不能跨模型套用 |
| `thinking_budget` | 有手动预算能力且开启时才发送；必须小于 max_tokens |
| `max_tokens` | 统一输出限制；Responses 协议转换为 max_output_tokens |
| `temperature` / `top_p` | 数值或 null（模型默认）；不支持时后端省略 |
| `stream` / `timeout` | 流式开关、超时秒数（5–900） |
| `image_generation` | 可选图片配置，由网页检测安装流程启用 |

网页保存使用原子替换。完整密钥只保存在本机配置中，网页读取返回密钥是否存在与尾号。配置、存档、权重和生成图片不进入 Git，分享工程时使用无密钥模板。

专用 Kimi OAuth 已移除。旧登录配置加载后转为未配置的 DeepSeek，不读取、刷新或转发旧登录凭证；选择新服务后保存会移除旧配置字段。原有通用 API 配置保留为 OpenAI 兼容服务。图片配置和玩家存档保留。

迁移机器可复制自己的配置文件，图片环境需在新机器重新检测。模型接入的代码职责见 [模型接入架构](模型接入架构.md)。

## 5. 项目目录

```text
role_play2/
├── 安装项目依赖.bat          安装 Node Web 依赖与构建网页
├── 启动游戏.bat              优先使用工程内 Node，启动本机后端
├── docs/环境配置指引.md      本指引，网页 /guide 也可打开
├── core/                    RPG 核心规则
├── modules/                 冒险本内容
├── web/
│   ├── config.json          本机模型设置，首次启动生成
│   ├── config.example.json  无密钥示例
│   ├── server/              配置、API、GM、存档和生图服务
│   ├── client/src/          Vue 网页源代码
│   ├── client/dist/         构建后的网页
│   ├── saves/               玩家存档
│   └── assets/              已生成图片
└── ai/
    ├── runtime/             本机 Node / 按需安装的 Python
    ├── vendor/ComfyUI/      按需安装的 ComfyUI
    ├── models/              按需下载的图片模型权重
    └── data/                安装任务、缓存与日志
```

完整复制工程离线使用时，需携带已安装的 Web 依赖和前端构建；已配置本地生图时，还需携带 `ai/runtime/python`、`ai/vendor/ComfyUI` 与 `ai/models`。线上文字模型离线时仍无法调用。

## 6. 可选本地图片生成

默认不配置、不检测、不加载。网页「设置 → 图片生成（可选）」打开「配置本地图片生成」，选择模型，点击「检测并配置」。

检测的是运行后端的机器，包括 GPU、显存、CUDA 算力和驱动、内存、CPU 逻辑线程以及磁盘空间。达标后自动下载并配置工程内 Python、ComfyUI、依赖和权重；已有完整安装会校验复用。只有全部成功才启用，真正生成图片时才启动模型。

| 当前配方 | NVIDIA 显存 | 内存 | CPU 逻辑线程 | 模型文件大小 |
|---|---:|---:|---:|---:|
| Z-Image-Turbo + Qwen3 | ≥ 16 GiB | ≥ 32 GiB | ≥ 4 | 约 19.27 GiB |
| Qwen-Image 2512 FP8 | ≥ 24 GiB | ≥ 48 GiB | ≥ 8 | 约 28.00 GiB |

当前自动安装策略还要求 Windows x64、CUDA 算力 ≥ 8.0、NVIDIA 驱动 ≥ 570.65，并需要额外的程序、依赖和临时磁盘空间。以网页检测报告为准；这些是项目当前配方的保守门槛。完整 Qwen-Image 2512 配方尚未完成本机实际生图验证。

不达标时网页给出失败项并建议使用图片 API；图片 API 目前只提供提示，尚未实现接入。关闭图片开关会停止项目创建的生图进程、取消配置任务，保留已下载文件供下次复用。完整说明见 `ai/README.md`。

## 7. 常见问题

| 现象 | 处理方式 |
|---|---|
| 找不到 Node / npm 或版本过低 | 安装 Node.js 22 以上的 LTS，重新打开终端；也可使用工程内完整 Node/npm |
| 启动提示缺少 Web 依赖或构建产物 | 运行 `安装项目依赖.bat`，成功后重启 |
| 安装出现 npm 网络错误 | 检查网络与本机代理，再运行依赖安装脚本；不要删除自己的配置或存档 |
| 网页显示未配置或示例回复 | 在设置填完整 API 地址、模型 ID、认证方式和所需密钥，再保存 |
| 测试成功但刷新又是旧配置 | 测试不保存，必须点击「保存配置」 |
| 401 / 403 | 检查密钥、账号权限和服务地域；更换地址后需填写新密钥 |
| 404 | 检查基础地址及其 `/v1` 等路径；确认服务选择对应 Messages、Responses 或 Chat Completions 协议 |
| 400 / 模型不存在 / 温度不支持 | 刷新模型目录，按模型能力选择思考模式和等级；确认输出长度与预算合法 |
| 超时、连接拒绝或流式失败 | 检查服务是否启动、网络/代理和端口；按需提高游戏超时，尝试关闭流式输出 |
| 游戏回复不能正确结算 | 基本连接成功不保证输出协议质量，使用遵守系统提示并能输出 JSON 的聊天模型 |
| 配置无法保存 | 确认工程目录可写、JSON 合法，避免只读或管理员权限目录 |
| 端口 8000 被占用 | 给启动脚本传其他端口，如 8001 |
| 本地图片配置失败 | 查看网页失败项和 `ai/data` 中安装记录/日志，重试时复用下载断点 |

## 8. 开发验证

在工程根目录运行：

```powershell
npm.cmd --prefix web test
node web/server/engine/verify-parity.mjs
npm.cmd --prefix web/client run build
```

`npm test` 使用离线模型或本机假服务、临时配置与内存存档，不使用个人线上 API Key。parity 校验使用独立夹具，避免写入玩家存档。本地 GPU 实际出图验证会加载权重，应按 `ai/README.md` 中的显式验证命令执行。

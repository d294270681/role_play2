# 前端界面与战斗扩展

## 使用方式

启动游戏后打开 http://127.0.0.1:8000/。已有存档会按本机选择载入；第一次使用可点击「选择或新建存档」。文字模型尚未配置时，先在设置中填写 API，或明确选择演示模式。安装与 API 字段说明见 [环境配置指引](环境配置指引.md)。

界面由左侧功能导航、顶部冒险与模型信息、核心资源条和主工作区组成。桌面「冒险」页同时显示故事与状态摘要；点击「专注阅读」可收起摘要。手机通过左上角菜单切换功能。

更新已运行的旧服务后，请关闭原游戏服务窗口并重新运行 `启动游戏.bat`，再刷新网页。后端权限与解锁视图需要重启才能生效。

| 页面       | 展示的真实数据                                                   | 操作                                                                    |
| ---------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 冒险       | 剧情、行动、骰子、插图、建议；摘要展示地点、进度、线索与已知人物 | 执行行动、选择建议、跳过打字、停止显示、查看插图                        |
| 角色档案   | 背景、属性雷达、技能、资源、特质、状态和经验                     | 查看档案、消耗已获得的经验成长、按需生成头像                            |
| 世界地图   | 地点连接图、当前位置、可前往地点、路线耗时与风险、地点描述与行动 | 查看详情、缩放/滚动地图、明确点击「前往」、填写地点行动、按需生成地点图 |
| 装备背包   | 已携带物品、真实数量、备注、资金与负重                           | 搜索、填写使用物品的行动；获得和消耗由回合结算                          |
| 进度与威胁 | 剧情中已出现的分段进度钟、格数、公开后果                         | 查看；建立与推进由行动、事件和 GM 结算                                  |
| 人物关系   | 已相识人物的公开资料、关系刻度、相识记录和已知状态               | 搜索、填写人物互动；不能直接调整关系或新增人物                          |
| 线索板     | 已发现与已解决两列卡片、解决比例                                 | 沿线索调查；发现与解决后自动记录、归档                                  |
| 事件与日志 | 已触发与待处理事件、最近 40 条记录、已解锁事件索引               | 查看日志、搜索已解锁事件；不预览未来事件牌                              |
| 战斗准备   | 防御、格斗/射击/先手基础加值、资源、状态、随身物品和特质         | 查看准备情况、跳转角色与背包                                            |

所有图表使用当前存档或后端公开快照。雷达与进度钟是本地 SVG；物品与人物暂无图片时显示图标或姓名首字。图片生成保持可选，点击配置入口才进入设置；未配置时不会自动加载 ComfyUI 或模型。

### 阅读与操作

- 功能页切换保留当前故事和行动草稿。地图、人物及建议按钮只填写草稿；发送或按 Enter 才执行行动。
- Shift + Enter 换行；输入框处理中文输入法的确认按键。
- Alt + 1 至 Alt + 9 按左侧顺序切换功能；Escape 收起手机导航。设置与存档弹窗打开时不响应功能快捷键。
- 玩家页面不提供自由编辑世界资料的功能。获得物品、认识人物、发现线索、建立威胁后，由最终回合结算更新；回合进行中仍可查看资料。
- 物品、人物和线索按钮只填写行动，发送后才进入剧情。玩家不能手动完成线索、增加关系、推进进度或改数量；角色成长会校验并扣除真实经验。
- 地图选中地点只打开详情。「前往」才消耗时段并触发后端移动规则。没有地点卡的路线端点标为外部路线，不能直接进入。
- 「停止显示」结束当前浏览器接收剧情；服务端继续结算保存，前端回读结果，完成同步后才能再次行动。
- 「冒险与存档」管理冒险本和三个槽位。空槽可新建，覆盖已有槽位需要确认；换槽清除上一角色的行动草稿。

## 开局、解锁与结算

初始装备、资金和已知关系来自所选角色卡；之后通过探索、对话、购买、使用或事件获得变化。作者在角色卡的「关系」栏明确登记开局已知人物，NPC 卡的默认态度只供 GM 裁决。港城开场出现的老魏已登记为初始已知关系。

第一次相识时，GM 即使保持关系为 0，也必须用 relations 登记公开记录。新发现使用 clues_add，查明后使用 clues_done；道具数量通过 items 的增量或设定结算；进度与威胁用 clocks 建立和推进。页面接收确认后的 SSE 状态与解锁索引，刷新或重新载入后仍读取同一存档。

新 NPC 的原始卡片、秘密与未触发事件仍供 GM 使用，玩家只能获取已解锁的公开资料。旧档中的未互动默认态度记录在公开视图中隐藏，旧文件不被删除或重写。party 在现有协议中是 NPC 动态状态集合，不表示每个人都在同行。

玩家编辑接口只允许 spend_xp。直接修改世界状态返回 403，伪造 GM 标记不会绕过限制。当前没有网页 GM 编辑模式；内部引擎编辑函数保留给作者工具和校验。

## 组件职责

| 位置                                                                 | 职责                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------ |
| `App.vue`                                                            | 布局、快捷键、核心资源条、弹窗、连接状态和提示               |
| `components/LeftSidebar.vue` / `TopBar.vue`                          | 功能导航、冒险信息、模型和存档入口                           |
| `components/StoryStream.vue`                                         | 剧情阅读、骰子/插图、行动输入与草稿                          |
| `components/AdventureOverview.vue`                                   | 当前冒险的快捷摘要与功能入口                                 |
| `components/WorkspacePanel.vue`                                      | 装配领域面板；换本/换槽/换页时重建局部表单                   |
| `components/panels/`                                                 | 角色、地图、背包、进度、关系、线索、事件、战斗准备           |
| `components/GaugeMeter.vue` / `ClockDial.vue` / `AttributeRadar.vue` | 可复用的资源、进度与属性图表                                 |
| `ui.js`                                                              | 视图定义、地图布局、资源警告、负重、开场文字整理；不访问 API |
| `store.js`                                                           | 会话与公开状态、导航、行动草稿、SSE、保存/编辑/移动/配置     |
| `api.js`                                                             | HTTP 与 SSE 协议                                             |
| `styles.css` / `theme.js`                                            | 共享视觉、响应式布局、组件主题与减少动画                     |

数据通过后端结算保存。领域面板调用 store 动作，图表只接收数据。前端导航和图形布局不会修改地图源数据、角色规则或保存格式。

公开资料的计算集中在 `web/server/progression.js`；HTTP 与 SSE 共用 `routes/shared.js` 的公开视图。`web/shared/playerActions.js` 定义前后端共同的玩家操作范围，GM 结算继续使用规则引擎的结构化补丁。

## 后续接入战斗

**当前只实现战斗准备展示，没有战斗回合、敌方数值、攻击按钮或战斗 API 调用。** 基础加值表示属性加技能；实际判定由规则引擎计入骰子、状态与临时修正。

接入时保留工作台与共享资源组件，将 `CombatPanel.vue` 扩展为交锋工作区：

1. 上方显示先手顺序、当前行动者、轮次与阶段。
2. 中部用参与者卡展示双方公开生命、防御、状态和可观察资源。
3. 操作区根据回合可用行动显示攻击、移动、防御或其他规则允许的选项。
4. 日志复用判定卡及统一结算说明，展示伤害、代价和状态变化。
5. 地图或故事页提供明确的进入战斗入口，结算后回到冒险展示结果。

战斗状态机与伤害结算留在服务端。前端发送行动意图，渲染确认后的公开状态；沿用模块/槽位标识、槽位锁和会话版本，防止重复行动、迟到响应覆盖新档或断线状态不一致。敌方秘密、GM 备注和未公开能力继续由公开视图筛选。

历史记录提到的 M9 战斗分支仍需评审和集成，本次没有合并。接入前需对齐现有成长费用、状态修正、行动耗时与存档可靠性；已有准备页面不代表战斗可用。

## 验证

当前实现通过 100 项 Node 回归、29 项 JavaScript/Python 规则一致性检查和 Vite 构建。Chrome 使用内存存档和本地假模型验证无自由编辑控件、API 拒绝直接修改、探索回合自动获得物品/相识/发现线索/建立进度、后续消耗与归档、合法经验成长、刷新恢复以及九页手机布局；无浏览器错误或组件警告。

真实玩家存档与配置前后哈希一致，未调用线上模型或启动生图。验证截图在被 Git 忽略的 `ai/data/unlocks-*.png`；回归位于 `web/server/routes/reliability.test.mjs`、`web/client/src/store.test.mjs` 和 `ui.test.mjs`。前一版本的界面、模型配置、地图移动和断流恢复验证详见开发记录。

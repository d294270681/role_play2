# 创建 RPG 本

根据用户在 `$rpg-create` 后给出的本名或构想，或当前对话中的建本要求，创建新的 RPG 本。输入来自实际消息，不依赖 Kimi 的参数占位符。

## 定位项目与读取规范

- 优先使用当前工作区中同时含 `modules/README.md` 和 `core/rules.md` 的项目根目录。若当前目录是项目子目录，向上定位；也可从本 skill 目录向上三级找到所属项目。下文路径均相对此根目录，不把本创建在 skill 目录中。
- 读取 `modules/README.md`，确认目录结构、`module.md` 格式及解耦纪律。
- 读取当前 `core/rules.md`，所有难度、伤害、危险度、关系值和进度钟按当前规则结算；不以 `.tower` 中旧任务说明替代现行规则。
- 读取 `core/event-deck.md`、`core/item-dex.md`、`core/world-map.md`、`core/character-template.md` 和 `core/save-state.md`，使用对应模板；模板内示例不是新本的当前状态。
- 列出 `modules/` 下已有的本，新目录不能与它们重名。目录名使用小写英文或拼音加连字符，如 `wasteland-radio`。

## 收集构想

沿用用户已经提供的设定。只有缺失信息会明显改变成品时，才合并为一次简短提问：

- 题材与基调，如民国侦探、废土求生、仙侠门派。
- 分级：全年龄 / 青少年 / 成人。
- 玩家角色：预设角色，或开局按 core §1.4 自建。
- 规模：小（1 个地区、3–4 个地点）/ 中（2 个地区、6–8 个地点）。
- 是否需要题材专属机制，如魔法、理智值、门派武学。

用户说“你看着办”时自行确定合理方案，完成后说明采用的设定。

## 生成文件

写入 `modules/<本名>/`：

1. `module.md`：frontmatter 填 `name`、`title`、`engine: core`、`tone`、`rating`；写简介、文件清单、规则覆盖和开局。`name` 与目录名一致。
2. `setting.md`：世界观、势力（各有一个目标和一个威胁进度钟）、主线谜团或目标、题材专属机制。专属机制注明对 core 哪一节的替换或追加，判定仍使用 2d6 + 属性 + 技能及规则规定的修正。
3. `world-map.md`：使用 core 地点模板。至少有一个危险度 0 的据点；每个地点至少 2 个可用行动，其中至少一个无需战斗；附路线表。
4. `event-deck.md`：至少 12 张本专属事件，d66 六类各 2 张，使用 core 事件模板；未覆盖的格子注明回退到 `core/event-deck.md`。
5. `item-dex.md`：6–10 件本特有道具，普通装备回退到 core。
6. `characters/`：玩家完整卡 1 张；选择自建时提供示例卡。重要 NPC 3–5 张完整卡，各有动机、秘密和翻脸条件；敌人可用简卡。
7. `saves/save-state.md`：第 1 天 · 晨的初始存档，写好开局地点、角色资源、进度钟及关系值，与开局和角色卡一致。若本有明确的时段覆盖，使用覆盖后的起始时段。

## 自检

发现问题先修正再交付：

- `module.md` 的文件清单覆盖生成的内容；清单中的文件或目录均存在。
- 属性各从 1 起，再分配 8 点，合计 14，建卡单项上限 4；技能分配 6 点，单项上限 2。
- 生命、精力、防御值、携带格按 core §1.3，决心按 §3.4 计算，并计入合法特质或本专属规则修正。
- 事件和地点中的主动判定注明属性、技能及难度；固定难度只用 7 / 9 / 11 / 13 / 15。对抗判定明确双方组合。
- 存档里的进度钟在设定或事件中有对应的满时后果；关系值、物品、地点和时段相互一致。
- 内容符合 `rating`；所有人物均为成年人，不写涉及未成年人的性内容。
- 修改范围仅为新本，没有改动 `core/`、已有本或既有玩家存档。

## 交付

列出生成文件，概括世界观和开局，说明用户交由你决定的设定。给出 Codex 的启动示例：`$rpg-load <本名>`。新建本不自动开始游戏，除非用户同时要求开局。
